# H01 HumorArena-CN：人类成对偏好评测平台

## 一句话提案

把当前“好笑/不好笑”网页升级成面向中文文字笑话和图片 Meme 的开放式、可复现成对竞技评测 Harness。

## 摘要

幽默的绝对评分噪声很大，而成对选择更接近日常判断。HumorArena-CN 随机展示同场景的两个匿名候选，收集用户选择、平局、都不好笑以及原因标签，再通过 Bradley-Terry/Elo 和不确定性采样形成动态排行榜。平台同时为 Benchmark、Prompt 优化、模型训练和产品选择提供统一数据接口。

## 核心目标

- 支持文字、模板 Meme 和原创图片 Meme。
- 支持模型、Prompt、Agent 配置和训练 Checkpoint 的匿名对战。
- 支持总体榜单、场景榜单、机制榜单和受众榜单。
- 记录候选完整生成 Trace，但不向评价者暴露模型身份。
- 用最少比较得到稳定排名，降低标注成本。

## 系统设计

```text
Experiment Registry
-> Candidate Pool
-> Pair Scheduler
-> Blind Web UI
-> Preference + Reason
-> Quality Control
-> Bradley-Terry/Elo Aggregator
-> Dashboard + Export API
```

每次比较随机交换左右位置，并允许四种选择：A 更好、B 更好、差不多、都不好笑。原因标签包括不贴场景、没反转、太像 AI、太旧、看不懂、图文无关、冒犯和见过类似内容。

## 研究问题

- RQ1：Arena 成对选择是否比 Likert 评分具有更高重测稳定性？
- RQ2：自适应配对比随机配对能节省多少标注量？
- RQ3：产品真实用户与受控实验标注者的偏好差异有多大？
- RQ4：同一模型的不同 Prompt 版本是否存在可重复的排名差异？

## Pair Scheduler

比较以下调度策略：

- 完全随机。
- 相近 Elo 对战。
- 不确定性最大化。
- 覆盖优先，保证每个场景和机制都有比较。
- 新系统冷启动探索。
- 受众分层调度。

调度器必须设置曝光上限，避免同一内容被过度展示和记忆。

## 质量控制

- 重复 Pair 检测个人一致性。
- 明显优劣的 Attention Check。
- A/B 相同内容检测随机点击。
- 最短阅读时间和异常速度检测。
- 图片加载失败、文字溢出和移动端可读性日志。
- 标注者可举报隐私、抄袭和伤害内容。

## 评价与实验

平台自身通过排名恢复误差、置信区间宽度、标注效率、重测一致性和跨群体稳定性评价。使用合成偏好和人工真实偏好双重仿真，验证聚合算法不会因曝光不均产生虚假赢家。

## 预期贡献

1. 中文幽默生成的标准化人类评测基础设施。
2. 一个可公开复用的 Arena 数据格式和 SDK。
3. 对幽默成对评测调度效率与偏差的实证研究。
4. 为后续所有训练与 Benchmark 提供共同地面真值。

## 风险与伦理

在线实验必须取得明确研究同意，并允许用户只使用产品而不贡献研究数据。排行榜可能被流量来源、曝光策略或少数高频用户操纵，因此需设置用户权重上限、异常检测和分层报告。

## 资源与周期

当前产品已经具备 Pairwise API 和反馈页面，预计 8-12 周可完成研究版。需要 1 名研究工程师、1 名前端/全栈工程师和 1 名统计研究者。
