# M02 DualRenderer：共享幽默意图的文字与图片生成

## 一句话提案

先生成模态无关的幽默意图，再由文字 Renderer 和图片 Meme Renderer 分别表达，研究笑点能否跨模态保持同时又发挥各自优势。

## 摘要

“先写完整笑话，再生成配图”会让图片退化成插图；“先找图，再硬写字幕”又可能失去真实场景。DualRenderer 引入共享 `HumorIntent`，其中只描述社会事实、预期、揭示、目标、机制和受众，不预先固定最终句子或画面。文字 Renderer 负责节奏和措辞，Meme Renderer 负责视觉隐喻、信息分工和排版。

## 方法与共享 HumorIntent

```json
{
  "emotional_truth": "真正被说中的生活事实",
  "public_reading": "用户最初理解",
  "revealed_reading": "包袱后的重新理解",
  "target": "被调侃的对象或制度",
  "mechanism": "幽默机制",
  "benign_frame": "为何可以笑而不是纯伤害",
  "audience": "目标受众",
  "must_preserve": ["关键因果", "关系张力"]
}
```

## 文字 Renderer

生成铺垫、Punchline 和可选 Tag，优化信息释放顺序、句长和结尾位置。它不得加入图像才会提供的信息，也不得解释共享意图。

## 图片 Meme Renderer

先选择三条路径之一：

- `template retrieval`：检索有许可的反应模板。
- `original reaction image`：生成不含文字的原创反应画面。
- `multi-panel`：生成聊天截图、伪系统弹窗或四格。

随后生成 `visual literal`、`metaphor mapping`、字幕槽位和阅读顺序。最终文字由程序化排版器叠加，保证中文准确和可读，不把文字生成交给图片模型碰运气。

## 研究问题

- RQ1：共享意图能否提高跨模态一致性和场景贴合？
- RQ2：同一个笑点在文字和图片中需要怎样不同的信息压缩？
- RQ3：哪类机制适合模板，哪类需要原创画面或多格叙事？
- RQ4：联合训练是否优于两个完全独立的生成器？

## 实验

比较文本先行、图片先行、独立规划和共享意图四种系统。进行跨模态恢复：从文字版本预测 HumorIntent，再生成图片；从 Meme 恢复 HumorIntent，再生成文字。测量语义保持和模态特有增益。

## 评价

- 单模态人类幽默偏好。
- 跨模态场景与意图一致性。
- 图文互补而非重复的评分。
- 删除图片或删除文字后的幽默下降量。
- 中文排版错误、OCR 可读性和移动端阅读时间。
- 生成成本、模板许可覆盖和端到端延迟。

## 预期贡献

1. 一种统一文字笑话和图片 Meme 的可解释生成架构。
2. 证明图像不应只是文字笑话的后处理插图。
3. 一套衡量跨模态语义保持与模态独有贡献的指标。
4. 可直接产品化的模板、原创反应图和多格三路 Router。

## 风险与伦理

共享意图可能限制视觉创意；端到端图片模型也可能出现文字、人物和版权问题。应保留多个视觉计划，并在最终合成前运行可读性、相似度和安全门禁。
